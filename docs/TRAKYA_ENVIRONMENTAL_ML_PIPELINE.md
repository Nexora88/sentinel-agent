# Trakya Environmental ML Pipeline

## Scope

A source-controlled pipeline for labeled environmental observations in Trakya, initially targeting fire/event detection and integration with the existing map and satellite analysis. This change adds data validation and split preparation only; it does not claim that an environmental model has been trained or validated.

## Non-negotiable data gate

Every input row must point to a source in `data/trakya/source-register.json`. The source must have `approval_status: "approved"` and non-empty `license`, `source_url`, `access_basis`, and `label_method`. A maintainer must independently review the source's terms, permitted collection, attribution, privacy, redistribution, and ML/model-weight rights. The registry intentionally starts empty, so processing fails closed until approval evidence is added. Do not commit secrets, personal data, raw satellite scenes, or large datasets to Git.

## CSV contract

Required columns: `sample_id,event_id,timestamp,latitude,longitude,label,source_id`. Coordinates are checked against a broad Trakya bounding box; refine it against a reviewed official boundary before production use. Labels must be supplied by a documented process, not generated by this script. Keep label definitions and uncertainty explicit in the dataset card.

## Prepare splits

```bash
python tools/prepare_trakya_environmental_dataset.py \
  --input /path/to/approved-labeled-observations.csv \
  --registry data/trakya/source-register.json \
  --output-dir /path/to/prepared-splits
```

The script validates provenance and coordinates, rejects duplicate sample IDs, and assigns entire `event_id` groups to train/validation/test so observations from the same event cannot cross split boundaries. It writes split CSVs and a manifest with input/registry SHA-256 hashes, split counts, class counts, and event IDs. A split manifest is an audit artifact, not proof of model quality. Review class balance and time/geographic coverage before training.

## Evaluation gate

Before any release, report at minimum: confusion matrix, precision, recall/sensitivity, specificity, F1, false alarms per monitored area/time, missed-event rate, calibration, latency, and uncertainty. Report confidence intervals and performance by season, geography, sensor, cloud/quality condition, and event type where sample size permits. Freeze the test set before tuning; do not use test results for feature selection or threshold tuning. Compare against a simple baseline and an independently reviewed reference set. Include negative examples and near-miss cases.

## Model and map integration

Keep ingestion, preprocessing, model inference, and map rendering separate. Every model output should include timestamp, geometry, class/probability, model version, input/source references, and quality flags. Treat detections as decision support, not confirmed incidents; expose uncertainty and a human verification workflow. Fail safely when imagery is stale, missing, cloudy, or the model is unavailable. Do not display synthetic/demo detections as real satellite observations.

## Acceptance checklist

- [ ] Source terms, access basis, privacy, attribution, and training rights approved and recorded.
- [ ] Label protocol documented; independent label review completed.
- [ ] Dataset and registry hashes recorded; duplicate and invalid records rejected.
- [ ] Event-level split checked for zero overlap and adequate class coverage.
- [ ] Baseline and model evaluated on a frozen independent test set.
- [ ] False-alarm and missed-event rates reported with confidence intervals.
- [ ] Map/satellite integration tested with stale/missing input and model failure.
- [ ] CI and domain review pass; no claim of readiness without recorded evidence.
